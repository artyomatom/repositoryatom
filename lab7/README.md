# Архитектура пакета
## Проект организован как единый Python-пакет, содержащий три вложенных пакета (lab4, lab5, lab6), каждый из которых копирует логику соответствующей лабораторной работы.

### В корневом __init__.py настроен явный экспорт через __all__, что предотвращает засорение пространства имён и обеспечивает стабильный публичный API.

### Использованы относительные импорты (from .module import ...), что делает пакет самодостаточным и позволяет перемещать его без изменения путей.

### Каждый модуль разделён по уровням сложности: solution.py (базовая реализация), tests.py (pytest), optimized.py/class_decorator.py/multithreaded_generator.py (Well-done улучшения).
# CLI интерфейс (Typer)
## Реализован в launcher.py. Основные особенности:
### Использованы аннотации типов и декораторы @app.command для автоматической генерации справки.

### Параметры передаются через typer.Argument и typer.Option, что обеспечивает валидацию ввода на уровне фреймворка.
Реализованы команды: count (подсчёт элементов), sequence (расчёт последовательности), calc (калькулятор с замыканием), random (генератор), demo (демонстрация всех функций), info (информация о пакете).
Обработка ошибок вынесена в typer.Exit и HTTPException-совместимые сообщения, что гарантирует корректное завершение при некорректном вводе.
# GUI приложение (Tkinter)
## Реализовано в gui_app.py с использованием стандартной библиотеки tkinter и расширения ttk:
### Интерфейс построен на основе ttk.Notebook, разделяющего функционал на 4 вкладки: Lab 4, Lab 5, Lab 6, Результаты.

### Использованы LabelFrame для группировки элементов ввода, ScrolledText для лога результатов, messagebox для обработки исключений.

### Привязка событий выполнена через command=lambda: ..., что позволяет передавать параметры в обработчики без создания промежуточных функций.

### Реализована защита от блокировки основного потока: все вычисления выполняются синхронно, но в рамках лёгких операций, не требующих асинхронности.

# Веб-приложение (FastAPI)
## Реализовано в web_app.py как RESTful API:
### Использованы Pydantic-модели (CountRequest, SequenceRequest, CalculatorRequest, RandomRequest) для строгой валидации входящих JSON-данных и формирования типизированных ответов.

### Эндпоинты разделены по HTTP-методам: GET для чтения/генерации, POST для расчётов с передачей тела запроса.

### Реализована обработка ошибок через HTTPException с кодами 400 (некорректные параметры) и 422 (валидация Pydantic).

### Автоматически сгенерирована интерактивная документация Swagger UI (/docs) и ReDoc (/redoc).

### Запуск осуществляется через uvicorn, поддерживающий асинхронный цикл событий.

# Тестирование
## Написаны интеграционные тесты с использованием pytest.
### Применены параметризация (@pytest.mark.parametrize), фикстуры (@pytest.fixture) и мокирование (unittest.mock.patch) для изоляции ввода/вывода.

### Проверены граничные случаи: пустые структуры, недопустимые типы, большие значения n, деление на ноль, некорректный JSON.

```
@app.post("/api/calculate", response_model=CalculatorResponse)
async def api_calculator(req: CalculatorRequest):
    if req.operation not in "+-*/":
        raise HTTPException(400, "Неподдерживаемая операция")
    calc = make_calc(req.operation, req.initial)
    for val in req.values:
        result = calc(val)
    return CalculatorResponse(result=result, operation=req.operation, steps=len(req.values))
```
